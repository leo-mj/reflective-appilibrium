# Audit, 2026-11-13

Phase 1: findings only. No application code was changed. Two test files were
added, which assert each verified logic defect as *still open* — the convention
of `app/e2e/known-issues.spec.js`, so both pipelines stay green and a fix turns
the matching test red:

- `app/src/audit/open-defects.test.js` (15 tests)
- `backend/tests/test_open_defects.py` (5 tests)

Ids below (L1, U1, C1 …) are the ones those tests use.

## How it was checked

- Read: the three `CLAUDE.md` files, `skill/re-relations-reference.md`, both CI
  files, and the code under the priorities named in the brief.
- Ran: Vitest (111 files, 1935 tests, green) and pytest (green) before adding
  anything; the 20 new tests after.
- Browser: Playwright scripts against the demo build and against the backend
  build with the real FastAPI server (no key), each at 1440×900 and 390×844.
  Flow: start, add two judgments and a principle, relate them, add a
  `precludes` argument, read Coherence, withdraw, close the round, export,
  re-import, then import a hand-written Argdown map. **The flow completes in
  all four combinations**, with no console error in the demo build.

Not checked: the GitLab pipeline itself; any LLM route with a real key; the
Playwright suite (`npm run test:e2e`) was not run. Local runs used Node 22 and
Python 3.13, where CI uses Node 24 and Python 3.12.

Sizes: S under about 50 lines with tests, M 50–200, L more.

## Findings, by severity

### Data loss or a wrong RE result

**L1 · Long wording makes a process unreadable to the app, and deletes its draft** — logic, verified

- *What happens.* No field caps what is typed. `validateState` caps every
  string: log text 5 000, explanation and reason 2 000, topic 500
  (`app/src/utils/importMarkdown.js:353`, `:299`, `:440-443`, `:464`). Revising
  a 2 600-character statement writes the log entry `J1 — text: <old> → <new>`,
  over 5 000 characters. From then on Import refuses the exported file, and
  `loadDraft` — which validates and, on failure, calls `clearDraft()`
  (`app/src/utils/draftStorage.js:76-82`) — deletes the autosaved draft on the
  next visit. A 2 001-character explanation or withdrawal reason does the same.
- *Should.* Whatever the app writes, it reads back.
- *Evidence.* Tests "L1" (three cases).
- *Fix.* Cap the inputs at the validator's bounds (`maxLength` plus a counter),
  shorten the log's diff of long wordings, and stop `loadDraft` deleting a
  draft it cannot validate (keep it, offer its raw export). M.

**L3 · A rejected element that is revised is held now and rejected in playback** — logic, verified

- *What happens.* Revise is offered on rejected cards
  (`TextTabCards.jsx:110`). `handleEditSave` adds a `reinstated` event only
  for a *withdrawn* element (`useElementActions.js:82-85`); `rewordElement` and
  `mergeElementPair` do the same (`stateUtils.js:529-534`, `elementMerge.js:163`).
  The element's `status` becomes `revised`, but `foldHistory` keeps it
  `rejected` (`stateUtils.js:119-123`). History, `stateAtRound`, and the
  backend's `status_at_step` (`rethon_scoring.py:206-228`) go by the fold, so
  History's scores count the element as a commitment to its negation while the
  Simulate tab counts it as held.
- *Evidence.* Test "L3".
- *Fix.* Record `reinstated` before `revised` for rejected items too, in the
  three places; the same for a withdrawn *relation* revised through
  `handleRelEditSave` (`useRelationActions.js:62-78`, read, not tested). S.

**L2 · Rejecting a suggestion takes no step; at step 0 it breaks every later assist request** — logic, verified in two halves

- *What happens.* `handleRejectElements` and `handleRejectRelations` add an
  item and a log entry at `prev.round` without advancing it
  (`useElementActions.js:254-283`, `useRelationActions.js:464-490`). CLAUDE.md
  ("Steps and rounds") lists a rejection among the changes that are a step. In
  a new process the item is stamped `addedRound: 0`, `rejectedRound: 0`, log
  `round: 0`. The backend requires `ge=1` for all three
  (`backend/models/re_state.py:124`, `:136`, `:213`), and every assist client
  sends `state.elements` (`judgmentsClient.js:12` also sends the log), so the
  requests after a first-thing rejection are refused with 422.
- *Evidence.* Frontend test "L2", backend tests `test_L2_*`. Not reproduced
  end to end: that needs a key.
- *Fix.* Make a rejection a step (one line each, plus tests), which also makes
  it an entry `canCloseRound` sees. S. See Q1 before choosing.

**L6 · A log entry's `findings` are shown nowhere** — logic and usability, verified

- *What happens.* The panel's Log, History's log box and the export's Log
  section print `changes` only (`LogSection.jsx:39`, `LogOverlay.jsx:79`,
  `exportMarkdown.js:318`). `findings` holds what CLAUDE.md says the log
  records: for an Argdown import the undercuts and whole-argument relations
  left out, untyped statements read as judgments, the halved `><`, ignored
  status tags; for a merge which elements were fused and how many relations
  were dropped; for an applied simulation the depth, weights and achievement
  "enough to run it again". These survive only inside the `re-state` JSON.
- *Evidence.* Test "L6". In the browser: a map with one undercut and one `><`
  imports with a log line naming neither.
- *Fix.* Print `findings` under `changes` in the three places. S.

**L9 · Coherence lists a tension from a joint argument whose other premise is withdrawn** — logic, verified

- *What happens.* `computeCoherence` filters relations one by one
  (`coherence.js:99-115`), so of "P1 and J1 jointly preclude J2" with J1
  withdrawn it keeps the P1 link and reports `P1 jointly precludes J2`.
- *Evidence.* Test "L9".
- *Fix.* Treat an argument as live only when all its premises are held. S.

**L7 · Process merge: fused premises and superseded links** — logic, verified

- *What happens.* (a) Two incoming premises fused into one element arrive as
  two identical `jointly_entails` links of one argument
  (`mergeStates.js:275-299`); `mergeElementPair` retypes the same case.
  (b) Links a revision replaced (`supersededBy`) are carried in and counted as
  relations added, against "a superseded link is the record, not the position".
  (c) Two identical elements *inside* the incoming file are fused with each
  other, reported as "identical to an existing element", and the preview shows
  no text for them (`mergeStates.js:217-223`, `:199-203`).
- *Evidence.* Tests "L7" (a, b); (c) from a probe run.
- *Fix.* Dedupe premises and retype as `elementMerge` does; drop superseded
  links before merging; word (c) separately. S–M.

**L8 · Argdown export rewrites an argument that has a `possible` premise** — logic, verified

- *What happens.* `buildArgdown` drops each *relation* touching a `possible`
  element (`exportArgdown.js:255-257`), so "J1, J2 ⊢ P1" with J2 `possible` is
  written as "J1 ⊢ P1". Reachable in questionnaire mode.
- *Evidence.* Test "L8".
- *Fix.* Drop the whole argument. S.

**L4 · Import validates fields, not the graph** — logic, verified

- *What happens.* `validateState` accepts duplicate element ids, relations to
  ids that do not exist, self-loops, and a joint link with no `argumentId`. It
  also drops `reinstatedRound` and `withdrawals`, which `legacyHistory` still
  reads (`stateUtils.js:41-45`), so an older file's reinstated element comes
  back with `status: active` and a history that says withdrawn.
- *Evidence.* Tests "L4" (two cases).
- *Fix.* Refuse duplicate ids; drop dangling and looping relations (as stray
  group members are dropped); whitelist the two legacy fields. S–M.

### Blocks a task

**U1 · Supports, conflicts and undermines are hidden until a menu switch is found** — usability, verified

- *What happens.* ☰ → Content → All relations is off by default
  (`REState.jsx:95`). A new process then offers no Relation tab, no `+ Rel`,
  no Relations section. "Relate them" can only be done as an argument. An
  imported Argdown map in loose mode — the default, and what the prompt in
  Import from text asks for — shows its `+>` and `->` nowhere: in the test map
  two of seven elements appeared unconnected, and nothing said that relations
  were hidden. The phone legend's "3 hidden" is the only cue.
- *I am not proposing to change the default*: `coherence.js:76-80` records why
  arguments-only is the default. The gap is that nothing announces it.
- *Fix.* When the state holds dialectical relations that are not drawn, say so
  with the count and a button that turns them on (graph legend and the Import
  log line); name the switch in the empty-process guide. S–M.

**U2 · No way to open a file from the landing page** — usability, verified

- *What happens.* The landing page offers Resume, the demo, and Start. To
  re-import an export one must start a throwaway process (answering the
  replace-draft dialog if a draft is on offer) and then use ☰ → Import.
- *Fix.* An "Open a file" action on `HomePage`, through the existing
  `handleImportFile`. S–M.

### Friction

**L5 · The same relation can be added twice** — verified. `handleAddRelation`
checks nothing (`useRelationActions.js:359-396`); the duplicate is a step, a
second edge, and "Covers: J1, J1" in the export. Test "L5". Fix: refuse an
exact from/type/to duplicate that is not withdrawn, in `checkRelation`. S.

**U3 · An untouched relation form says "From ≠ To"** — verified. Both ends are
empty and equal (`addPanelShared.js:295-298`). Test "U3". The phone's dialog
instead opens on J1 → J2 *supports*, which a Save without reading adds. Fix:
ask for the two ends; open both forms the same way. S.

**L10 · The relation matrix is enforced nowhere, and omits two pairs** — doc and code disagree, verified

- CLAUDE.md says which pairs "may legally hold which relation is the full
  matrix" in `skill/re-relations-reference.md`. Nothing reads it: not the add
  bar (`checkRelation`), not `validateState`, not the relations prompt or
  router. The matrix has no Judgment → Theory or Principle → Theory section, and
  says nothing about the four inferential types. Test "L10".
- *My view: change the documents, not the code.* Wide RE needs J → T: the
  independence constraint asks that background theories be supported by
  considered judgments other than those the principles systematise (Daniels,
  "Wide Reflective Equilibrium and Theory Acceptance in Ethics", *Journal of
  Philosophy* 76(5), 1979, 256–282). Forbidding the pair would make that
  support unrecordable. Proposed: add the two sections to the reference, and
  reword CLAUDE.md from "legally" to what the matrix is — guidance for
  suggesting relations. S, docs only.

**U4 · quick_score is asked with no elements** — verified. In the backend
build a new process posts an empty list, which the schema refuses
(`rethon_schemas.py:79`, `min_length=1`): two 422s in the console per start.
Fix: skip the call below three elements, which the server answers with nulls
anyway. S.

### Cosmetic, or defensive

- **L11** — `rethon_arguments` relies on the client to leave out superseded
  links (`rethon_caps.py:57-62`). Every current caller does. Test
  `test_L11_*`. Fix: filter on `superseded_by` server-side. S.
- **L12** — links sharing an `argumentId` but not a conclusion or type become
  one argument (`rethon_tasks.py:101-113`). Import only (L4). Test `test_L12_*`.
- A reinstated element that was once revised is stored `active` and folds to
  `revised` (`useElementActions.js:236`, probe run). No effect on scores.
- A rejected suggestion's origin is the literal `"llm"`
  (`JudgmentElicitTab.jsx:274`), not `llmOrigin(model)`.
- `mergeElementPair` leaves the removed element's pin in `state.pins`.
- Argdown export: `*`, `_` and `\` in a statement are read back as markup and
  lost; a statement beginning `===` makes the exported file unparseable.
- `app/CLAUDE.md` calls `AddBar` "the app's only add form"; the phone uses the
  dialogs in `components/graph/`, whose submit reads Save, not Add.
- At 1440px with All relations on, the section pills wrap and push the search
  box to a row of its own.

## Suspected, not verified — and questions for you

- **Q1 · Does declining a suggestion mean holding its negation?** A rejected
  suggestion is stored as a `rejected` element, and rethon receives every
  `rejected` element as a negative commitment (`rethon_scoring.py:37-50`;
  confirmed by a probe). "I do not hold this" and "I hold that this is false"
  are different commitments, and only the second belongs in the position. If
  the first is what Reject on a suggestion card means, account and
  faithfulness are computed against commitments the user never made. This
  decides how L2 should be fixed.
- **Q2 · What History's achievement chart plots.** `compute_score_per_round`
  runs a full simulation per step and returns its *final* score
  (`rethon_scoring.py:290-319`): the achievement of the equilibrium reachable
  from each step, with faithfulness measured against that step. CLAUDE.md
  reads as though it were the achievement of the position held at the step. I
  did not check the chart's wording against this.
- **Q3 · Playback is exact for wording and status only.** History events carry
  no type or confidence, so a change to either shows at every earlier step.
  Read, not tested.
- **Q4 · `.dockerignore` under Buildah.** The root file is an allowlist (`*`,
  then `!backend/`). I could not run Buildah here; if the GitLab image jobs are
  green today, this is fine.

## CI: GitHub and GitLab

**C1 · A Playwright bump passes GitHub and fails GitLab** — verified by reading

- The tag and the lockfile agree today (`v1.63.0-noble`,
  `@playwright/test` 1.63.0). Dependabot's monthly grouped PR updates
  `app/package-lock.json` and knows nothing of `.gitlab-ci.yml:119`. GitHub
  downloads the new browser; GitLab fails with "Executable doesn't exist".
- *Fix.* A small script comparing the two, run by the frontend test job in
  both pipelines, so the mismatch is red on the PR. S.

**C2 · The backend image is started on GitHub only, and the exception is not written down** — verified by reading

- GitHub's `backend-image` job starts the container and checks `/api/health`
  and that `/docs` is 404. GitLab builds and pushes the image without starting
  it. The header of `.gitlab-ci.yml` documents one exception,
  `ci/check-stack.sh`; this is a second.
- *Fix, either.* (a) Name it in the header. S. (b) A GitLab job after
  `images` that uses the pushed backend image as its own `image:` and runs the
  same two requests — no daemon needed. M, and I cannot test it.

**C3 · Smaller**

- `quay.io/buildah/stable:latest` is unpinned, so the GitLab build tool can
  change without a commit.
- `playwright.config.js:88` selects the `github` reporter whenever `CI` is
  set, which GitLab also sets: harmless `::error` lines in its log.

**Checked, no drift.** Python 3.12 and Node 24 in both; the same commands for
lint, Vitest, pytest, both `npm audit` levels and `pip-audit`, with the same
blocking and informational split; the e2e job installs the backend in both;
reports are kept 14 days in both. Neither Dockerfile uses BuildKit-only syntax,
both name their base images with a registry, and no test reads a `GITHUB_*`
variable (`basePath.test.js` covers its absence). The two new test files run
in both pipelines with no change to either CI file.
